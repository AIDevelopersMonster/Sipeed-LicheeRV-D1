# LicheeRV D1 Dock — рабочий HDMI на Ubuntu 22.10 Sipeed

**Дата аппаратного подтверждения:** 29 октября 2026 года  
**Статус:** `D1_HDMI_PHYSICAL_PASS`, `D1_HDMI_FRAMEBUFFER_COLOR_PASS`, `D1_WIFI_INTERNET_PASS`  
**Политика:** сохранять рабочий HDMI; не изменять загрузчик, ядро, DTB/Device Tree и видеодрайверы ради экспериментов.

> Этот документ фиксирует реально наблюдавшийся стенд. Он не является новой инструкцией по пересборке драйвера HDMI. Рабочее состояние достигнуто загрузкой готового образа; точные внутренние параметры DTB, видеоразрешения и исходник цветового теста пока не сохранены. Не подменять неизвестное предположениями.

## 1. Рабочая конфигурация и отличия от Ubuntu 24.04.3

| Параметр | Подтверждено |
| --- | --- |
| Плата | Sipeed LicheeRV D1 Dock, Allwinner D1, RISC-V XuanTie C906 |
| Образ | `sipeed_d1_ubuntu22.10_20221116.img` — имя файла, сообщённое оператором |
| Система | Ubuntu 22.10 (`riscv64`) |
| Ядро | `5.17.0-1003-allwinner` |
| microSD | примерно 32 ГБ; корневой раздел при входе отображал 28,87 ГБ |
| HDMI | реально показывает загрузку, приглашение `login:`, текст, затем цветные полосы |
| Активная HDMI-консоль | `tty1` |
| Framebuffer | `/dev/fb0`; `cat /proc/fb` → `0 sun4i-drmdrmfb` |
| DRM | `/dev/dri/card0`; `platform-display-engine-card` указывает на card0 |
| Xorg / Wayland / LightDM | соответствующих процессов не обнаружено |
| `DISPLAY` | пустой: на HDMI работает Linux-консоль, не графический desktop |
| Wi-Fi | `wlan0` UP, получен DHCP-адрес `192.168.1.89/24` во время теста |
| Маршрутизация | gateway `192.168.1.254` |
| Интернет | `ping -c 3 1.1.1.1`: 3/3 ответа, 0% потерь, среднее 19,053 мс |
| SSH | вход под `d1user` по паролю подтверждён через `/dev/pts/0` |
| UART | отдельный сеанс `root` на `ttyS0` |
| Физический дисплей | отдельно подключённый HDMI-экран; точные тайминги/модель не записаны |

**Сравнение:** на Ubuntu 24.04.3 LTS (`6.8.0-60-generic`) запуск Freedoom через X11/SSH подтверждён, но HDMI там не был аппаратно подтверждён. Ubuntu 22.10 Sipeed — **отдельная** конфигурация, не следует переносить из неё видеонастройки на другое ядро без испытаний.

## 2. Как достигнуто рабочее состояние

1. Использован названный выше готовый IMG для D1 и microSD; загрузка завершилась в Ubuntu 22.10 с ядром `5.17.0-1003-allwinner`.
2. Физический HDMI-дисплей сам показал сообщения `systemd`, затем `Ubuntu 22.10 ubuntu tty1` и `ubuntu login:`. **Установка рабочего стола и настройка Xorg для этого не потребовались.**
3. Доступ по UART: приглашение `root@ubuntu:~#`. Wi-Fi был настроен и проверен отдельно.
4. Для SSH был создан пользователь `d1user`; он подключился через MobaXterm. Прав `sudo` при проверке у него **не было**; вход `root` через SSH по паролю запрещён текущей конфигурацией.
5. Фотографией подтверждён вывод строки на HDMI в активную `tty1`. Передача была выполнена в привилегированном терминальном сеансе; **надпись «VIA SSH» в тексте на экране сама по себе не доказывает, что команда исполнялась из SSH**.
6. На HDMI показаны пять широких горизонтальных полос (красная, зелёная, синяя, жёлтая, белая); на фотографии оператора видно имя `d1_hdmi_test.py`. Исходный код этого исполнявшегося файла **в беседе не получен**; публиковать выдуманную реконструкцию как оригинал нельзя.

Таким образом подтверждён цветной графический вывод. FPS, двойная буферизация, пропускная способность framebuffer и совместимость с SDL/KMSDRM пока **не измерены**.

## 3. Диагностика, не изменяющая HDMI

Через существующую SSH-сессию:

```bash
uname -a
cat /etc/os-release
cat /proc/fb
ls -l /dev/fb0 /dev/dri/card0
cat /sys/class/tty/tty0/active
cat /sys/class/graphics/fb0/virtual_size
cat /sys/class/graphics/fb0/bits_per_pixel
tty
who
ip -br addr show wlan0
ip route
```

Автоматический **только читающий** сбор параметров: [`scripts/d1-hdmi-inventory.sh`](../../scripts/d1-hdmi-inventory.sh). Он не запускает видеоприложения, не перезапускает службы, не пишет в `/dev/fb0`.

Ожидаемые уже наблюдавшиеся значения:

```text
$ cat /proc/fb
0 sun4i-drmdrmfb

$ cat /sys/class/tty/tty0/active
tty1

$ tty      # в MobaXterm / SSH
/dev/pts/0
```

Фактические значения `virtual_size`, `bits_per_pixel`, режима HDMI и stride в разговоре **не представлены**; их необходимо получить и сохранить отдельно до нового графического теста.

## 4. Проверенный минимальный вывод текста в HDMI-консоль

На UART-консоли `root@ubuntu:~#` успешно использовалась запись текста в активный `tty1`:

```bash
printf '\n=== HELLO FROM RISC-V D1 ===\n' > /dev/tty1
```

Это пишет **только символы в консоль**, не меняя HDMI-конфигурацию. Видимое сообщение на фотографии имело текст `HELLO FROM RISC-V D1 VIA SSH`.

Не путать интерфейсы: `tty1` — активный HDMI, `ttyS0` — UART, `pts/0` — отдельный SSH-терминал. Обычные команды в SSH не отображаются на HDMI автоматически.

## 5. Wi-Fi, SSH и безопасность

Проверено:

```text
wlan0            UP    192.168.1.89/24
default via 192.168.1.254 dev wlan0
ping 1.1.1.1: 3 transmitted, 3 received, 0% packet loss
```

IP-адрес получен через DHCP и может измениться. Подключение по SSH под `d1user` работает; не включать парольный SSH-вход `root` ради удобства. Ранее наблюдалось `permitrootlogin without-password`, `passwordauthentication yes`. `ss` показал прослушивание TCP/22 даже при `systemctl is-active ssh` → `inactive`; механизм сокетной активации **не был подтверждён**.

Ubuntu 22.10 больше не поддерживается обновлениями безопасности: не использовать эту конфигурацию как доступный из интернета сервер. Не публиковать реальные пароли, ключи и Wi-Fi-секреты.

## 6. Правила сохранения рабочего HDMI

**Запрещено без независимой резервной копии microSD:**
- обновлять/менять ядро `5.17.0-1003-allwinner`, U-Boot, SPL, DTB/Device Tree;
- менять bootargs, разметку SD, видеодрайверы, конфигурацию дисплея;
- выполнять `apt upgrade` или устанавливать графическую среду как «обязательное исправление»;
- экспериментировать с неизвестными параметрами DRM modesetting.

Перед следующим рисованием сначала снять **побитовую резервную копию рабочей microSD на ПК**, не перепутав источник и назначение. На Windows требуется проверка физического диска; не записывать образ поверх эталонной карты.

Дополнительно сохранить контрольную сумму исходного `sipeed_d1_ubuntu22.10_20221116.img` на Windows:

```powershell
Get-FileHash 'C:\path\to\sipeed_d1_ubuntu22.10_20221116.img' -Algorithm SHA256
```

Сумма **пока неизвестна**. Не подменять её хешем Ubuntu 24.04.3 — это другой образ.
