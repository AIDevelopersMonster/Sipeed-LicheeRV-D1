# D1_FREEDOOM_RENDER_PASS — Freedoom на реальном RISC-V C906

**Дата:** 29 октября 2026 года  
**Плата:** Sipeed LicheeRV D1 Dock, Allwinner D1 / XuanTie C906  
**ОС:** Ubuntu 24.04.3 LTS Server, Linux 6.8.0-60-generic, riscv64  
**Способ вывода:** MobaXterm X server через SSH X11 forwarding и Wi-Fi 2,4 ГГц  
**Итог:** `D1_FREEDOOM_RENDER_PASS`; **`NOT_PLAYABLE_OVER_X11`**

## Фактический результат

На D1 установлены и запущены **Chocolate Doom 3.0.0** и **Freedoom: Phase 1**. Пользователь предоставил два скриншота работающего окна на Windows: титульный экран Freedoom и сцену первого уровня с игровым HUD и оружием. Игра запущена на самом D1; окно отображено через удалённый X11 на компьютере с MobaXterm.

В ходе эксперимента пользователь сообщил: **«Задержки огромные, играть невозможно... но графика есть»**.

Поэтому доказаны запуск движка, загрузка ресурсов WAD и формирование игрового изображения, **но не установлена пригодность интерактивной игры**. FPS, сквозная задержка и загрузка CPU отдельными измерениями не подтверждены.

## Установленные программы

В Ubuntu подтверждены:

~~~text
/usr/games/chocolate-doom
/usr/share/games/doom/freedoom1.wad
/usr/share/games/doom/freedoom2.wad
~~~

## Последовательность воспроизведения

1. Запустить X-сервер MobaXterm, подключиться к D1 по SSH с включённым X11 Forwarding.
2. Убедиться, что `DISPLAY` выставлен, и проверить открытие графического окна: `xclock`.
3. Проверить наличие движка и игровых данных.
4. Запустить Freedoom без звука:

~~~bash
echo "$DISPLAY"
command -v chocolate-doom
ls -l /usr/share/games/doom/freedoom1.wad
SDL_AUDIODRIVER=dummy chocolate-doom \
  -iwad /usr/share/games/doom/freedoom1.wad \
  -window -nosound
~~~

В начале попыток был получен вывод `Failed to initialize video: x11 not available`; диагностический тест X11 завершился `X11_FAIL`. После восстановления X11 через MobaXterm окно `xclock` появилось, а Freedoom открыл и титульный экран, и игровой уровень.

В отдельном предложении упоминался запуск с параметром `-1` для уменьшения масштаба окна. **Результат этого дополнительного варианта пока не получен**, поэтому улучшение задержек не заявляется.

## Инженерная интерпретация

- Реальный процессор **XuanTie C906 способен исполнять Chocolate Doom** и строить изображение Freedoom в Ubuntu на RISC-V.
- При использованной конфигурации **удалённый X11 через SSH и Wi-Fi не обеспечивает приемлемого отклика для игры**.
- Без измерений нельзя отделить задержку X11/SSH/Wi-Fi от затрат на программный рендеринг и масштабирование. Нельзя делать вывод, что **сам C906 неспособен обеспечить играбельный DOOM при локальном выводе**.
- Этот опыт нельзя выдавать за подтверждённый запуск на HDMI или за проверенную частоту кадров.
